# Описание проекта

## Назначение

MyService Platform - система заказа химчистки, клининга, дезинсекции и дезинфекции.

Клиент получает единый способ выбрать услугу, узнать предварительную стоимость и согласовать время. Мастер получает календарь, данные заказа и понятный набор статусов. Владелец сервиса получает единый учёт заказов и простую статистику.

## Исходная ситуация

Сейчас основные заказы приходят по рекомендациям и телефону. Дата, время и контакты записываются в личный календарь или заметки. Подтверждение выполняется вручную. Общая история заказов и статистика не ведутся.

Из-за этого сложно развивать продажи, подключать других мастеров и контролировать загрузку.

## Цель продукта

Создать понятный веб-сервис, который поддерживает заказ от первого расчёта до завершения работы.

Сервис должен:

- показывать доступные услуги;
- давать предварительный расчёт цены;
- принимать заказ;
- хранить историю изменений;
- поддерживать расписание и назначение мастера;
- отправлять уведомления;
- учитывать оплату и результат работы;
- разделять доступ по ролям.

## Пользователи

Клиент создаёт заказ и следит за его состоянием.

Мастер видит назначенные работы и меняет статус выполнения.

Оператор подтверждает заказ, уточняет данные и назначает мастера.

Администратор управляет пользователями, ролями, услугами и настройками.

## Границы первой версии

В первую версию входят:

- каталог услуг;
- предварительный расчёт;
- создание заказа;
- просмотр заказа;
- расписание;
- назначение мастера;
- уведомления;
- роли и права;
- журнал изменений.

Оплата, отзывы, аналитика и PWA входят в последующие версии.

## Технический прототип

Первый прототип содержит один рабочий сервис заказов. Он принимает заказ через REST API, сохраняет его в PostgreSQL и создаёт событие для RabbitMQ через transactional outbox.

Остальные сервисы сначала будут описаны в требованиях и архитектуре.

- RabbitMQ;

- Pytest;
- GitHub Actions;
- Keycloak на следующем этапе.

## Ограничения

Проект создаётся как демонстрационный пример. Он не обрабатывает реальные данные клиентов и не разворачивается в рабочей среде.

Фронтенд на первом этапе не является приоритетом. Для проверки API используется Swagger UI или Bruno.

## Результат

Репозиторий должен показывать полный путь от бизнес-проблемы до проверяемого технического решения.
