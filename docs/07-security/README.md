# Безопасность

## Вход

Для целевой системы используется Keycloak и протокол OpenID Connect.

Клиент может создать заказ после подтверждения телефона. Для сотрудника используется отдельная учётная запись.

Для ролей MASTER, OPERATOR и ADMIN обязательна двухфакторная аутентификация.

## Ролевая модель

| Действие | CLIENT | MASTER | OPERATOR | ADMIN |
|---|---:|---:|---:|---:|
| Создать заказ | Да | Нет | Да | Да |
| Посмотреть свой заказ | Да | Нет | Да | Да |
| Посмотреть назначенный заказ | Нет | Да | Да | Да |
| Подтвердить заказ | Нет | Нет | Да | Да |
| Назначить мастера | Нет | Нет | Да | Да |
| Изменить статус работы | Нет | Да | Да | Да |
| Управлять услугами | Нет | Нет | Нет | Да |
| Управлять ролями | Нет | Нет | Нет | Да |
| Смотреть аудит | Нет | Нет | Нет | Да |

Роль не заменяет проверку владельца объекта. Клиент получает только свой заказ. Мастер получает только назначенный заказ.

## Персональные данные

Телефон и адрес хранятся в сервисе заказов. Они не передаются в событиях и не записываются в технические логи.

Доступ к контактам мастера прекращается после закрытия заказа согласно политике хранения.

## Аудит

Система сохраняет вход сотрудника, просмотр контактных данных, подтверждение заказа, назначение мастера, изменение цены и изменение роли.

Запись аудита содержит пользователя, действие, объект и время. Секреты и токены в аудит не записываются.

## Статус прототипа

Авторизация в первом прототипе не реализована. API предназначен только для локального запуска. Перед публикацией API в интернет требуется подключить Keycloak, HTTPS и проверку владельца заказа.
