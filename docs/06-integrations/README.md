# Интеграции

## Синхронный обмен

Клиентские интерфейсы обращаются к API Gateway по HTTPS. Gateway проверяет токен и передаёт запрос нужному сервису.

Внутренний REST используется только тогда, когда вызывающей стороне нужен немедленный результат.

Все REST-контракты имеют версию в пути: `/api/v1`.

## Асинхронный обмен

Сервисы публикуют события в topic exchange RabbitMQ. Имя exchange для заказов - `orders.events`.

Первое событие прототипа - `order.created.v1`.

Routing key совпадает с именем события.

## Правила событий

Каждое событие содержит:

- `eventId`;
- `eventType`;
- `eventVersion`;
- `occurredAt`;
- `orderId`;
- `serviceType`;
- `status`.

Имя, телефон и адрес клиента не передаются.

Получатель обязан обрабатывать повторную доставку по `eventId`.

После нескольких неуспешных попыток сообщение направляется в dead letter queue. Число попыток задаётся для каждой очереди.

## Надёжность публикации

Order API не отправляет сообщение напрямую. Он сохраняет заказ и outbox-событие в одной транзакции.

Worker публикует событие с режимом delivery mode `persistent` и ждёт publisher confirm. Только после подтверждения поле `published_at` заполняется.

Если RabbitMQ недоступен, запись остаётся в outbox и будет обработана повторно.
